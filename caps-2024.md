# IT CAPS (2024 amendment) — full reference

**Source:** DBE *Curriculum and Assessment Policy Statement (CAPS), FET
Information Technology Grades 10-12* — `CAPS/CAPS_FET_Information_Technology_Gr10-12.pdf`
(the 2011 original) and `CAPS/CAPS_IT_Amendment_2024_Section3.pdf` (the
2024 amendment, which **replaces Section 3 and Section 4** and adds
Annexures A-C). Both are in this folder. Extracted with `pdftotext -layout`.

**What this file is for:** a token-cheap reference to check CAPS wording,
term placement, weighting or exam format without re-opening the PDFs - the
CAPS twin of [sags-2025.md](sags-2025.md). It is a faithful, cleaned
transcription of the CAPS text, not a teaching document. Which Pascal
lesson covers which CAPS content is in the platform's
`content/pascal/caps.php` (shown in each lesson's CAPS box on the course
page); the gaps it found are in [open-items.md](open-items.md).

**Scope - what's in and what's left out:**

- **In:** Section 2 (what IT is, aims, resources) from the original; the
  whole of the 2024 Section 3 teaching plan, every topic, Grades 10-12,
  term by term; the 2024 Section 4 (assessment, programme of assessment,
  Paper 1 and Paper 2 formats, PAT, cognitive and difficulty levels); and
  Annexures B (components and methods) and C (practical taxonomy).
- **Out:** Section 1 (the general CAPS preamble shared by every subject);
  the original Section 3 (it had Scratch in Grade 10 - replaced); Annexure
  A (a glossary of acronyms); and the topic-layout and progression
  diagrams, which are images in both PDFs with no extractable text.

**How CAPS differs from the SAGs, in one breath:** no subtopic numbers - the
content is a **suggested teaching plan per grade per term**, so a place in
CAPS is "Grade 10, Term 3, Solution Development". Six topics, not four.
Delphi is the named language (Java also allowed). Paper 1 **includes
databases through code** (SQL and data-aware components) with GUIs
provided; the IEB practical is text-based with no database connection.
Promotion weights differ (see §4).

Quoted wording is the CAPS's own, cleaned of PDF artefacts only. "(�N
weeks)" in the source is written "(~N weeks)" here.

## 1. Introduction to Information Technology (original Section 2)

**What IT is:** the study of the interrelated physical and non-physical
technologies used to capture data, process it into information, and
manage, present and disseminate it; solving problems through logical and
computational thinking; the components for electronic transmission,
access and manipulation of data and information.

**The six topics:** Solution Development, Communication Technologies,
Systems Technologies, Internet Technologies, Data and Information
Management, Social Implications. They overlap on purpose - e.g. social
implications are taught with the topic they arise from, not alone.

**Specific aims** - a learner will:
- use appropriate techniques and procedures to plan solutions and devise algorithms to solve problems using suitable techniques and tools;
- understand and use appropriate communication technologies for information dissemination;
- appreciate and comprehend the various systems technologies used in developing a computer-based system;
- understand that all ICT systems are built upon software engineering principles;
- understand and use Internet technologies for various tasks;
- comprehend and apply the concepts of data and information management to understand how a knowledge-driven society functions; and
- understand the social implications of ICTs and how to use ICT technologies responsibly.

**Time:** 4 hours a week. Grades 10 and 11: 35 teaching weeks + 5 of
exams. Grade 12: 28 teaching weeks + 12 of exams. (The original's
per-topic hours table predates the 2024 term plan below; use the hours in
§3's term headings.)

**Resources:** one networked computer per learner per period, enough
computers for the practical exam in two sittings, a printer, Internet,
a projector, and software. The development tool must have an IDE that
supports structured and object-oriented methods, a visual GUI builder
(WYSIWYG, component-based) and event-driven programming.

## 2. Content and scope per topic (2024 Section 3, overview)

- **3.1 Solution Development** - developing software in a planned,
  structured process, solving computational problems (including data
  problems) through logical thinking; event-driven, object-oriented and
  sequential programming. Grade 10: computational skills, algorithms,
  problem solving and programming in a high-level language with an IDE and
  GUI builder; controls, code and event handling. Grade 11: builds on it -
  the form class, attributes, methods and controls; manipulating a
  database through code. Grade 12: more advanced problems, basic OOP, SQL
  and manipulating a relational database. Computational thinking
  throughout; usability, HCI and software engineering reinforced.
  Algorithmic problem solving in Grade 10 comes first, on its own, with
  everyday scenarios - order and precision - then is integrated with
  programming. Learners should solve problems by identifying and analysing
  requirements, designing effective algorithms, converting them to code
  and testing against the requirements, and apply HCI principles to design
  functional user interfaces.
- **3.2 Communication Technologies** - network technologies, standards and
  protocols for transmitting data; e-communication; communication
  software; safety and security; new trends.
- **3.3 Systems Technologies** - hardware and software of a computer
  system; purchase and upgrade decisions; choosing hardware and software
  for a scenario; managing a system; elementary troubleshooting; trends.
- **3.4 Internet Technologies** - the Internet and WWW, Internet services
  and supporting technologies, how they benefit scenarios, trends.
- **3.5 Data and Information Management** - data and information
  (representation, classification), how business uses databases, social,
  legal and ethical issues, database design, DBMS software. Database
  design, queries and reports are linked to Solution Development.
- **3.6 Social Implications** - the digital age, the digital divide,
  responsible use of ICTs, safety and risk. Mostly integrated with the
  other topics, not taught alone.
- **3.7 Suggested teaching plan** - the minimum content per term. The
  order within a term is not prescribed; teachers make their own work
  schedules. Sub-topics are taught integrated, not stand-alone.

## 3. Suggested teaching plan (2024 Section 3.7)

### Grade 10

#### Grade 10, Term 1 (10 weeks / 40 hours)

**Systems Technologies: Basic concepts of computing (~1 week / 4 h)**
- What are digital technologies? Define Information Technology
- A general model of a computer: input, storage, processing, output and communication
- Main components of a computer system:
  - Hardware: input (keyboard, mouse), storage and memory (hard drive and memory), processing (CPU), output (monitor, printer), communication (NIC)
  - Software: system software (operating system) and application software; generic examples and uses; shareware, freeware, free open-source software (FOSS), proprietary software
  - Interdependency of hardware and software; hardware vs software
- Types of computers (purpose and uses): desktop, laptop, tablets, smartphones, server, embedded computers (microcontrollers)
  - Differentiate by primary use, processing power and size; classify by portability/mobility, processing power and usage
- Data and information: the difference; the information processing cycle (input, processing, output, storage, communication); uses of information in an organisation; why information is useful
- What is an ICT system? A general model (convey, manipulate and store data); examples (point-of-sale system, mobile phones)

**Data and Information Management: Data representation and storage (~2 weeks / 8 h)**
- Data, information and knowledge; what are data representation and data storage? Bits and bytes
- Number systems: decimal, binary, hexadecimal; converting binary <-> decimal and decimal <-> hexadecimal
- Digital character representation: ASCII and Unicode
- Data types and their storage: primitive (integer types, character types, floating point types, Boolean); other (text/string types)
- Data structures and collections of data storage: files, databases; reasons for data storage
- Computer file management: organising files; files, folders and drives; file specification (drive, path, filename, extension); file manager; hierarchical structure; reasons for a file structure; manipulating files and folders (cut, copy, paste, move, rename)

**Social Implications (~1/2 week / 2 h)**
- Software licence agreements (including Creative Commons), piracy, copyright, copyleft
- Social, ethical and legal issues of ICTs; economic reasons for using computers (saving paper, labour, communication costs, efficiency, accuracy, reliability)
- The digital divide: what it is, reasons, digitally enabled citizens
- Digital citizenship; digital footprint
- Advantages and disadvantages of using computers

**Solution Development: Introduction to algorithms (~2 weeks / 8 h)**
- Basic concepts: what an algorithm is; everyday examples (drawing a kite, folding a paper jet, a recipe); devising instructions for similar everyday tasks
- Basic IPO tables and flow charts: as tools to represent an algorithm; interpreting and developing them
- Algorithms to develop: smallest/largest of more than two values; swapping values; aggregates - sum, average (without loops); basic calculations (area, volume, VAT); whether a number is even; whether a number is a factor of another
- Produce an algorithm to solve a problem; trace an algorithm with a trace table; the value of accurate, well-tested algorithms; compare algorithms for sequence, precision and efficiency
- *Note:* this section introduces solution development through everyday scenarios; exploring generic algorithms lets learners devise algorithms for new problems and recognise problem types; explore several ways to solve the same problem.

**Solution Development: Introduction to solution development (~2 1/2 weeks / 10 h)**
- Programming, basic terms and the development environment
- Output; input (keyboard)
- Variables: naming conventions, assigning values, data types (integers, strings, floats, Boolean)
- Operators (+, -, *, /) and order of precedence; remainders (modulus)
- Comparison operators and logical comparisons
- Functions: random, round, square root
- Basic calculations (area, volume, VAT, simple formulae from other subjects)
- Basic conditional constructs (if and if-then-else)
- *Note:* apply algorithms such as swapping values, aggregates, isolating digits of an integer, smallest/biggest of two numbers, factor, even. *Delphi casting:* StrToInt, IntToStr, FloatToStr, StrToFloat, FloatToStrF

**Solution Development: Introduction to solution development using a high-level programming language (~2 weeks / 8 h)**
- The programming tool: IDE/GUI, basic terms, development environment
- Components (input/output); casting; formatting output (fixed, currency); event handling (click)

**Assessment (PoA):** 1 theory test.

#### Grade 10, Term 2 (10 weeks / 40 hours, including 2 weeks of exams)

**Systems Technologies: Basic concepts of hardware (~1 week / 4 h)**
- Input devices (what, where, for what): keyboards, pointing devices, scanners, pen, microphones, biometric devices, sensors
- Output devices: monitors; printers (ink, laser, 3-D) - compare by features, product, quality and speed; headphones/speakers
- Storage devices: hard drives, USB flash drives, SSDs, SD cards - compare by capacity, portability, technology (magnetic, electronic)
- Input/output devices: touch screens, game controllers, smartphone
- System unit: general function of motherboard, CPU and RAM; where the CPU and RAM are
- Ports and connectors: USB, HDMI, NIC
- Categorise hardware as input, output, storage, processing; primary memory vs secondary memory (storage)
- Compare a desktop's input, processing, output and storage with a smartphone/tablet's - same, different, why

**Systems Technologies: Basic concepts of system software (~1 week / 4 h)**
- Operating system: what it is; its role - general (programs managing hardware and software) and specific (user interface, I/O management); overview of file, disk, memory, storage and process management; types (stand-alone, network, embedded) linked to types of computers; examples (Windows, Linux, iOS, Android)
- Utility programs: what they are and are used for
- Device drivers: definition; installation, manual vs plug-and-play

**Communication Technologies: Networks overview (~1/2 week / 2 h)**
- What a network is; reasons (communication, sharing resources, centralisation, file and funds transfer, productivity, leisure); advantages and disadvantages
- Basic components: nodes (printer, servers, workstations); NIC (wired and wireless); communication media (wired and wireless); switch and router; network operating system (NOS)
- Communication media: UTP, fibre optic, radio waves, infrared - compare accessibility, coverage and security
- PAN, HAN, LAN/WLAN and WAN (coverage, where used); the Internet as a WAN
- Client-server vs peer-to-peer; access control

**Communication Technologies: Electronic communications (~1/2 week / 2 h)**
- What e-communication is; tools and their purpose: e-mail, web browser, cloud storage, instant messaging, chat rooms, video calls and VoIP, vlog, blog, webinars
- E-mail: uses; web-based accounts (create and access); e-mail addresses

**Social Implications (~1/2 week / 2 h)**
- Ergonomics, green computing, health issues
- E-communication in terms of accuracy, time, distance, cost, speed; responsible communication and netiquette
- E-mail best practice: To, Cc, Bcc, forward, reply, attachments, subject

**Solution Development: Software engineering principles (~1 1/2 weeks / 6 h)**
- What problem solving is; problem-solving steps (Polya, 1957):
  - Understand the problem - state it in your own words; what must be done; what is given, what is missing
  - Devise an algorithm, looking for patterns - related problems and known solutions; simpler or special cases; make a table, draw a diagram, guess and check, work backwards, identify sub-goals; present it as a flowchart or pseudocode
  - Carry out the plan (write the code)
  - Look back/test (trace tables) - check results against the problem; does it make sense; is there another solution?
- Apply them: smallest/largest of more than two values; even; factor; other relevant problems
- Software analysis tools: user stories (by the client, giving requirements); noun-verb analysis of user stories (nouns -> objects and state; verbs -> behaviour); acceptance tests (does the program meet the requirements?)
- Implement algorithms for general problems with the Term 1 and 2 constructs

**Solution Development: Introduction to solution development using a high-level programming language (~4 weeks / 16 h)**
- Comparison operators and logical comparisons (from Term 1)
- Conditional constructs (if, if-then-else) with Boolean operators; nested ifs; CASE
- Variables and relational operators, extended; Boolean logic (AND, OR, NOT, IN)
- String comparisons (basics)
- Basic validation (input and processing), e.g. testing for a negative number before a square root
- Events: form create, activate
- Debugging techniques; debugging with trace tables
- *Delphi string methods:* Length, UpperCase, UpCase, Trim

**Assessment (PoA):** a practical test; mid-year examination (1 practical + 1 theory paper).

#### Grade 10, Term 3 (10 weeks / 40 hours)

**Systems Technologies: Computer management (~1 week / 4 h)**
- Management tasks and OS utilities: the desktop; files and folders - naming conventions, common file types and extensions (association), compressed files, forms of text files, database/spreadsheet/presentation/word-processing documents, graphic, movie, sound and animation files, source code (Delphi only), object code, executables and shared/dynamically linked libraries, saving as another type or version and exporting
- Housekeeping: disk clean-up, updating, archive and backup, compress/decompress, security (firewall, anti-virus, spyware and adware control), installing/uninstalling software (custom and full installs, licence keys, activation codes), system settings (regional and language)

**Internet Technologies: Internet and WWW (~1 1/2 weeks / 6 h)**
- The Internet: what it is; IP addresses and domain names; connecting (ISPs, wired and wireless connections)
- The WWW: what it is; URL; web page and website
- Browsing and searching: web browsers and examples; accessing a website; search engines and examples; search techniques

**Social Implications (~1/2 week / 2 h)**
- E-mail and Internet threats: viruses, hoaxes, fake news, spam, phishing, e-mail spoofing, pharming
- Safe e-mail and Internet use; POPIA (basic understanding and purpose)

**Solution Development: Introduction to solution development using a high-level programming language (~5 weeks / 20 h)**
- Iteration: fixed, pre-conditional and post-conditional (for, while, repeat-until)
- String handling from first principles (no built-in methods): count occurrences of a character; position of a character; remove, replace, or add a character; extract a character or a substring
- String methods: length, left, right, position, copy, trim, delete, insert
- Algorithms: prime numbers; lowest common multiple (LCM) and greatest common divisor (GCD); finding a character in a string
- Simple applications combining graphics, iteration, conditions and the concepts covered
- A timer object for simple animations

**Solution Development: Software engineering principles and PAT (~2 weeks / 8 h)**
- Program persistence (to retrieve the previous state of a program)
- Project requirements: problem statement; research; user stories (who, what, limitations); a diagram of the program's functionality
- GUI design: apply HCI principles - grouping of components; panels and/or tabbed panes (no multiple screens)
- Implement each requirement: IPO; flowchart; test cases linked to user stories; code; test

**Assessment (PoA):** 1 alternative task (closed or open book, case study or integrated task); 1 practical test.

#### Grade 10, Term 4 (10 weeks / 40 hours, including 3 weeks of exams)

**Internet Technologies: Internet and WWW (~1/2 week / 2 h)**
- Internet services: online storage, synchronisation, collaboration; online shopping; social media

**Solution Development: Introduction to solution development (~1 week / 4 h)**
- Revise, consolidate and extend by developing applications that combine structures and features - identify and analyse requirements, design algorithms, code, test against requirements, HCI in the interface

**Solution Development: Software engineering principles and PAT (~3 weeks / 12 h)**
- Input and output with a text file (PAT only, optional): read a file into a list box; save a list box to a file - *Delphi: only LoadFromFile and SaveToFile*
- Finalise the PAT: build the solution from the planning; document it with comments

**Assessment (PoA):** examination - 1 practical, 1 theory paper. **Promotion mark:** final practical paper 20%, final theory paper 20%, PAT 20%, SBA 40%. The PAT is finished before the end-of-year exams.

### Grade 11

#### Grade 11, Term 1 (10 weeks / 40 hours)

**Systems Technologies: Hardware (~1 week / 4 h)**
- The motherboard: purpose and role; its components - BIOS chip, CPU, GPU, RAM, VRAM, ROM, slots and buses; modular design
- Expansion cards: purpose and role
- Data flow between components: buses (USB); point-to-point connections; storage -> RAM -> CPU; RAM -> VRAM -> GPU
- Cache memory and caching; memory in a computer system; ROM and RAM - role and characteristics
- Performance: differences between components, and caching (cache memory, web caching, disk caching)

**Systems Technologies: Software (~1 week / 4 h)**
- Operating systems compared by cost, size, hardware needed and platform
- Compilers and interpreters
- Processing techniques: multi-tasking, multi-threading, multi-processing (definition, comparison)
- Virtual memory (role and purpose)
- Virtualisation: what it is; virtual machines and their purpose

**Communication Technologies: Networks (~1 week / 4 h)**
- Physical aspects: media (UTP, fibre, Wi-Fi, 4G/5G, satellite); topology (star); physical limitations (access, bandwidth); connection devices (NIC, modem, switch, router/bridge); compare PAN, HAN, LAN, WAN by composition, media and capacity
- Network innovation: VoIP; Internet vs intranet vs extranet; VPNs; location-based computing (what it is; weather and traffic apps)

**Social Implications (~1/2 week / 2 h)**
- Social implications of location-based computing; ethical and legal issues of network use policies (AUP); capabilities and limitations of hardware and software

**Systems Technologies: Computer management (~1/2 week / 2 h)**
- Safety and security: human error (GIGO, accidents)
- Threats: physical access (theft, flash drives and portable media); hardware failure (storage, power); network vulnerability - malware (viruses, worms, Trojans, ransomware, spyware, rootkits, keyloggers, bots), social engineering (spoofing, phishing, pharming)
- Remedies: awareness training; access-controlled rooms, alarms; backup (including online), UPS; usernames and strong passwords, access rights, firewalls, anti-virus, validation (Captcha)

**Solution Development: Application development using a high-level programming language (~6 weeks / 24 h)**
- Nested loops: structure; algorithms - binary <-> decimal conversion; drawing simple shapes with a character such as a star
- Arrays: the one-dimensional array as a data structure; looping through items; aggregates (sum, average, product), minimum, maximum
- Searching (linear and binary) and sorting (bubble and selection); parallel arrays
- String manipulation with string methods: inserting and deleting characters; position of a character; finding a character or substring; length
- Date and time objects: changing, formatting, calculating; *Delphi:* TimeToStr, DateToStr, IsLeapYear
- *Notes:* compare the efficiency of the sorting and searching algorithms (e.g. with trace tables); learners need apply only ONE of each for practical assessment; extend built-in methods and the idea of parameters/message passing

**Assessment (PoA):** 1 practical test, 1 theory test.

#### Grade 11, Term 2 (10 weeks / 40 hours, including 2 weeks of exams)

**Communication Technologies: Electronic communications (~1 week / 4 h)**
- Mobile/wireless e-communication (purpose, writing style, audience): e-mail; microblog, SMS, instant messaging; video casting, podcasting, VoIP, video conferencing
- Mobile technology: devices (smartphones, tablets, laptops); mobile browser vs mobile app
- Wireless technologies: GPS, cellular generations (4G/5G), Bluetooth, Wi-Fi, access points; range and bandwidth (non-technical); connection speed - shaping, throttling
- Protocols: POP3, SMTP, IMAP, VoIP
- Data security: blockchain; passwords, encryption, multi-layer verification/authentication

**Social Implications (~1/2 week / 2 h)**
- Effects of digitalisation: the gig economy; online services (banking, reservations, e-learning); video conferencing and collaboration; social media and influencing; careers (digital forensic investigator, 3D architects and printing operators, privacy consultant, medical nanobot technician); the workplace (remote office, decentralised labour, office automation, robotics, AI)
- Protecting your online identity

**Data and Information Management: Database management (~1/2 week / 2 h)**
- DBMS: definition and functions; examples - proprietary (SQL Server, Oracle, Access), open source (PostgreSQL, MySQL)
- Database types by size and access: desktop/personal, server/centralised, distributed
- Careers: DBA, database programmer, analyst, project manager

**Solution Development: Application development using a high-level programming language (~5 weeks / 20 h)**
- Text files: what they are; physical vs logical file name; layout (end of line, end of file)
- Trace tables to show parameter passing; text files to fill other data structures
- Text file procedures: assign, overwrite, close, open for reading, read a line, write a line, open to add - *Delphi:* AssignFile, Rewrite, CloseFile, Reset, Readln, Writeln, Append
- Reading: exception handling; checking the file exists; one line or many; displaying the data; string handling in exercises
- Adding: overwrite or append mode; display the updated file; a formatted text report
- User-defined methods: purpose; functions and procedures and their difference; structure, calling statement and signature; arguments vs parameters; **value parameters only**; methods in problems
- Basic input validation techniques; validation using code constructs

**Solution Development: Software engineering principles and PAT (~1 week / 4 h)**
- Software development: define the problem; read the specification and analyse the requirements; design the interface and solution (logical solution, functionality and usability); code; test and debug; document, implement and maintain
- Planning techniques with any appropriate tools
- Dynamic instantiation of active and passive components (functions and procedures) - GUI design

**Assessment (PoA):** mid-year examination (1 practical, 1 theory paper).

#### Grade 11, Term 3 (10 weeks / 40 hours)

**Data and Information Management: Database design concepts (~3 weeks / 12 h)**
- Data, information, knowledge and decision making
- Quality data: accuracy, correctness, currency, completeness, relevance; validation - format, data type and range checks, check digit
- Using valuable information to build knowledge and make decisions
- Accessing and manipulating data: manual, electronic
- Grouping data: records and fields; field types and purpose (primary, alternate, foreign and composite keys); tables; relationships, referential integrity and ERDs
- Reporting on data
- A simple database without relationships: design the tables; maintain data (insert/add/import, delete, edit); process, sort, query

**Social Implications (~1/2 week / 2 h)**
- Computer and human error: inaccurate and invalid input; unverified data; software bugs; wrong hardware/software configuration
- Cybercrime: identity theft; business data theft; virus attacks (ransomware, malware)

**Solution Development: Application development using a high-level programming language (~4 1/2 weeks / 18 h)**
- Accessing a database through code: connect to a single-table database by giving its path in code
- A multi-form/multi-screen GUI with simple controls (functionality and usability)
- Simple database transactions in code: access fields and records in a dataset; navigate records; modify fields and records and apply changes; manipulate a dataset object; iteration and conditions
- Methods: parameter passing and return values with class methods of the form class
- Solutions with computational thinking and software engineering: generic algorithms; database transactions managed by methods or events; devise and motivate a specific algorithm; validate the solution against data (trace tables, watches, comparing output by hand)

**Solution Development: Software engineering principles and PAT (~2 weeks / 8 h)**
- Problem-solving steps and software engineering, reinforced
- Relationships between tables (optional): 1:M (e.g. register class -> pupils); two tables in a master-detail relationship with at least one foreign key; primary and foreign keys; simple ERDs
- A query on at most two related tables with multiple criteria

**Assessment (PoA):** 1 theory test or alternative assessment (closed or open book, case study or survey); 1 practical test.

### Grade 12

#### Grade 12, Term 1 (10 weeks / 40 hours)

**Data and Information Management: Database management (~1 week / 4 h)**

**Social Implications (~1/2 week / 2 h)**

  - Aggregate functions: SUM, MIN, MAX, AVG, COUNT, TOP; with GROUP BY and HAVING

  - Mathematical operators; date functions (day, month, year, date)

**Assessment (PoA):** 1 alternative task (closed or open book, case study or integrated task); 1 theory test.

#### Grade 12, Term 2 (10 weeks / 40 hours, including 2 weeks of exams)

**Systems Technologies: Computer management (~1/2 week / 2 h)**

- VR, AR and MR: what they are, uses, hardware and software needs, advantages, limitations
- Virtualisation: what it is, uses, benefits

**Social Implications (~1/2 week / 2 h)**

## 4. Assessment (2024 Section 4)

### 4.1 Informal and formal assessment

- **Informal (daily) assessment** - for learning: observation, discussion,
  demonstrations, self- and peer-assessment. Not recorded for promotion.
- **Formal assessment** - of learning: tests, exams, practical tasks,
  projects; marked, recorded and moderated. Assessment in IT should
  encourage computational thinking.

**Formal assessment structure:**

| | During the year | PAT | End-of-year exam |
|---|---|---|---|
| **Grade 10** | SBA 40%: 3 tests, 1 alternative task/test, 1 mid-year exam | 20% | 40%: written (theory, all topics) 20% + practical (Solution Development) 20%, 3 hours each |
| **Grade 11** | as Grade 10 | 20% | as Grade 10 |
| **Grade 12** | SBA 25%: 2 tests, 1 alternative task/test, 2 exams (mid-year, prelim) | 25% | 50%: written 25% + practical 25%, 3 hours each |

**Types of formal assessment:**
- **Project** = the PAT: planning/research, carrying out the task to criteria, producing a software product, decision-making, some innovation. The teacher sets clear criteria, keeps the scope manageable, provides resources and monitors.
- **Tests** - practical or written, a balance of both, at least 60 minutes, covering a substantial amount of content (not a series of small tests). Open-book tests need thinking and decision-making: written ones want paragraph answers with reasons; practical ones apply combined procedures to new situations.
- **Alternative assessment** - an *integrated task/test* (theory and practical together - e.g. database theory with database practical, an algorithm with its implementation, a trace table to debug a program) or a *case study* (an in-depth investigation of a real or simulated situation).
- Every test, task and exam spans the cognitive levels.

### 4.2 Cognitive and difficulty levels

| Level | Name | Description |
|---|---|---|
| C1 | Knowledge, remembering | Recall of factual/process knowledge in isolation - one step at a time; definitions (theory), known procedures/algorithms (practical) |
| C2 | Understanding, applying | Understanding steps/algorithms; translating between representations (e.g. a flow chart into a working program); using known routines in a familiar context with all information given |
| C3 | Analysing, evaluating, creating | Reasoning, planning a sequence of steps; seeing how parts form a whole; more than one approach; choosing the best solution; testing and troubleshooting; pattern recognition and generalisation; learners create their own solutions |

| Cognitive level | Paper 1 (practical) | Paper 2 (theory) |
|---|---|---|
| 1 Knowledge and remembering | 30% | 40% |
| 2 Understanding and applying | 40% | 40% |
| 3 Analysing, evaluating and creating | 30% | 20% |

**Difficulty:** D1 easy, D2 moderately challenging, D3 difficult, D4 very
difficult (to separate the top achievers) - for the average Grade 12
learner. Judged on content, stimulus (reading the question), task
(producing the answer) and expected-response (the memo) difficulty
(Leong, 2006).

| | D1 | D2 | D3 | D4 | Total |
|---|---|---|---|---|---|
| C1 | ~10% | ~10% | ~10% | - | ~30% |
| C2 | ~15% | ~15% | ~8% | ~2% | ~40% |
| C3 | ~15% | ~7% | ~5% | ~3% | ~30% |
| **Total** | ~40% | ~32% | ~23% | ~5% | 100% |

### 4.4 The PAT (20% in Grades 10-11, 25% in Grade 12)

- One extended task through the year, in phases: **planning**
  (understanding the task, requirements), **design** (interface and
  program design with any appropriate tools - no specific tool required),
  and **solution** (coding, testing, implementation, internal
  documentation). Agile methods are fine.
- Each task carries a declaration of authenticity.
- Grade 12: criteria set externally (by the examiner, moderated by
  Umalusi, sent to schools at the start of the year), administered and
  marked internally, moderated externally.

  the exam may run in two sittings.
- No overarching scenario; each question may have its own.

| Question | Skills tested | Marks |

- No large amounts of typing: data comes from the data disk, a text file
  or a database table. **All GUIs are provided.**
- Marks go to basic skills, constructs and problem solving - e.g. for
  choosing an iteration structure and for using it correctly - and reflect
  the time to solve, code and debug.

## 6. Annexure C - taxonomy for practical content

| C1 - lower order (30%) | C2 - middle order (40%) | C3 - higher order (30%) |
|---|---|---|
| **Code generator** - works at the level of single lines, code structures and routine procedures in isolation | **Program generator** - writes basic programs that combine concepts and structures | **Software developer** - writes solutions to new, unfamiliar or open-ended problems |
| Recalls isolated facts; uses bits of code on their own; knows syntax and semantics - can write a line or structure that does one thing (a processing statement, input or output, swapping two items); answers questions seen before in exactly the same context | Reads a program and says what each line does and what the program is for; writes programs seen before in a similar context; combines building blocks into valid programs; answers closed/scaffolded questions in a similar context, with or without new elements | Says how the parts of a program work together; optimises code; analyses, designs, plans, implements and tests a solution to a new problem; error catching (when, where, how); combines structures into new or adapted algorithms; links to a broader context; identifies patterns; generalises, abstracts and decomposes into sub-problems and modules; answers unseen, open-ended questions |
| *Cannot* see relationships or combine code to reach a goal | *Cannot* optimise, plan in detail, trace errors, or answer unfamiliar, unscaffolded questions | |
| Examples of isolated knowledge: a syntax rule; a statement (assignment); a built-in method (random); a structure (class definition); an algorithm (swap, sort); a process (reading a text file, filling an array); setting a property | Understanding: converting formats (a flow chart into code); reading code and giving its output. Applying: using a procedure, algorithm or structure in a similar context with new elements | Synthesis: combining concepts in a new context into a working whole - identifying the parts (sub-routines, data structures, I/O, algorithms) and deciding which structures to use |
